# Gufo extension registry

> **Draft** for [gufo-org/gufo#1075](https://github.com/gufo-org/gufo/issues/1075).
> Gufo does not read this registry yet: until it does,
> `gufo extension install <name>` explains that the registry is unavailable.

The registry lists extensions whose specific source revisions the Gufo
maintainers have reviewed. With it, users install an extension by name:

```sh
gufo extension install lfm3            # newest compatible reviewed release
gufo extension install lfm3@0.4.0      # a specific reviewed release
```

Without it, `gufo extension install <git-url>@<revision>` and local
directories keep working. Those print a warning, because nobody has validated
that code.

## What an entry promises

An entry in `extensions/<name>.json` means that, for every listed release:

- a maintainer reviewed the source **at that exact commit**, following
  [REVIEW.md](REVIEW.md), and approved the pull request that added it;
- the `digest` matches the tree at that commit, so the reviewed code is the code
  gufo builds, even if the source host is compromised or rewrites history;
- `version`, `api_version` and `platforms` match the extension's own
  `extension.json` at that commit.

It does **not** promise model quality or speed. Extensions document those
themselves, along with their limitations and their model weight licenses.
Review is a defense against malicious or careless code, not a sandbox: an
installed extension runs native code with the user's permissions.

## Format

```json
{
  "schema": 1,
  "name": "lfm3",
  "description": "LFM3 1.7B text, LFM3-VL 2B, LFM3-Audio 2B and d1-Omni 2B on Strix Halo",
  "homepage": "https://github.com/gufo-org/lfm3-gufo-extension",
  "license": "MIT",
  "maintainers": ["@octocat"],
  "source": "https://github.com/gufo-org/lfm3-gufo-extension",
  "releases": [
    {
      "version": "0.4.0",
      "revision": "967f5e13ad501e4a505988f20694fed1e442ead1",
      "digest": "sha256:ab5c3c91588e53432914e34a9a2f4ac4091a51d830b7372e6629b5e985ead6dd",
      "api_version": ">= 0.2.6",
      "platforms": ["linux"],
      "notes": "Optional release notes."
    }
  ]
}
```

The schema is [schema/extension.schema.json](schema/extension.schema.json).
Releases are listed newest first and never edited after merging: a fix is a
new release, and a withdrawn release is removed in its own pull request that
says why.

`index.json` combines every entry and is generated by
`tools/registry.py index`. CI fails when it is stale.

## How gufo uses it

The client contract `gufo extension install <name>[@<version>]` will follow:

1. Fetch `https://raw.githubusercontent.com/gufo-org/gufo-extension/main/index.json`
   over HTTPS.
2. Pick the newest release, or the named one, that lists the host platform and
   whose `api_version` the host satisfies. The compatibility series
   (`MAJOR.MINOR`) must equal the host's, and the host revision must be at
   least the requested one.
3. Install `<source>@<revision>` as for a Git source, then compare the
   recorded tree digest with `digest`. A mismatch aborts the install.
4. Record the registry name and release in `installed.json`. No
   unvalidated-code warning is printed; gufo names the reviewed release instead.

The digest is the one `gufo extension install` already records: SHA-256 over
every regular file outside `.git`, in path order, each as its relative POSIX
path, a NUL byte and its contents. `tools/registry.py digest <dir>` computes it.

## Add or update an extension

1. Tag or pick the commit to publish. Its `extension.json` must carry the
   version you list.
2. Compute the digest of a clean checkout of that commit:

   ```sh
   git clone https://github.com/you/your-extension && cd your-extension
   git checkout <commit>
   python3 /path/to/gufo-extension/tools/registry.py digest .
   ```

3. Add or extend `extensions/<name>.json`, run `tools/registry.py index` and
   `tools/registry.py check`, and open a pull request with the checklist from
   [REVIEW.md](REVIEW.md) filled in.
4. CI fetches each new release and verifies its manifest fields and digest.
   A maintainer reviews the source and approves.

```sh
python3 tools/registry.py check            # entries and index.json
python3 tools/registry.py verify lfm3      # fetch and compare every release
```

The tools need Python 3.10+ and Git only.
